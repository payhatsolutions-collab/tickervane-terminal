# AlphaNova: SEO, programmatic SEO and AI discovery

Audit date: 2 October 2026 (IST). Site: https://alphanova48.in/. Skills applied: seo-audit, programmatic-seo, ai-seo; schema for page markup.

## Outcome and scope

AlphaNova has a sound basic crawlable site, but little public coverage of the research workflows that distinguish its product. Six existing public pages returned 200 with self-canonical URLs and indexable metadata. The homepage retains a readable product overview after React mounts, and rendered JSON-LD contains WebSite, WebApplication and WebPage entities. The main opportunity is specific, useful screener documentation connected to the working tool.

Implemented locally: six curated screener guides, a guide hub, methodology and pricing pages; a build-time generator that shares the app’s exact preset rules; links into the correct interactive preset; internal links; a 15-URL sitemap; llms.txt and pricing.md. These changes are built, tested and **deployed to alphanova48.in on 2 October 2026**.

This audit covers source code, live public HTTP responses, a rendered production homepage, and local browser checks. It does not establish Google indexing, rankings, organic traffic, backlinks, Core Web Vitals or cross-platform AI citation rates. No Search Console or analytics property was accessed. No keyword volumes or authority scores are invented.

## Technical checks

- Live `/`, stock prices, stock market app, stock screener, delivery radar and about pages: HTTP 200, distinct titles and self-canonicals. Baseline recorded in `seo-live-check-2026-10-02.json`.
- Live robots.txt allows public pages and blocks `/api/`; references the sitemap. Preserved this policy. It already allows search crawlers through its wildcard rule.
- HTTP redirects to HTTPS with 308. `/index.html` returns 308 with `Location: /`. A deliberately nonexistent URL returned 404, not a soft 404. The Python baseline records the 308 as an HTTP exception; a separate header check confirmed its destination.
- Broker return page is noindex and excluded from the sitemap.
- Live HTTPS responses include HSTS and a content security policy. No separate certificate or exhaustive mixed-content audit performed.
- Rendered production homepage schema was inspected in the browser, not inferred absent from a text fetch. New guide schema was also inspected after rendering.
- New pages have one H1, self-canonicals, unique titles/descriptions, social metadata, visible modification dates and WebPage/CollectionPage plus BreadcrumbList JSON-LD. No invented ratings, authors or endorsements.
- All 15 sitemap pages and their internal destinations pass automated validation. Each guide is two ordinary links from the homepage, links back to its hub, and links to two relevant guides.
- Unknown query parameters cannot create new screener rules. Guide links choose only known preset IDs. App query variants remain canonical to `/` and are excluded from the sitemap.
- Mobile hub checked at 390 px: one-column cards, readable content and no horizontal overflow. Desktop guide, metadata and preset navigation checked in the browser. This is not a full accessibility certification or Core Web Vitals measurement.

## Programmatic SEO strategy

**Audience and conversion:** people researching Indian equities who need understandable screening rules. Primary conversion: opening a documented preset in AlphaNova. Secondary actions: inspecting a company, saving a screen and exporting results.

**Initial pattern:** `[research condition] + stock screener`, with a single page per distinct condition. No stock × industry × location Cartesian expansion. Search volume remains unmeasured; this is a bounded pilot based on implemented product capability and observed category results.

| Intent | Canonical path | Distinct value |
|---|---|---|
| Nifty 500 screener features | `/stock-screener.html` | Existing product overview; remains the broad category target. |
| Compare screening methods | `/screens.html` | Choose between the six documented research conditions. |
| Delivery accumulation screener | `/screens/delivery-accumulation.html` | Delivered quantity vs delivery share; distinguishes radar classification. |
| Volume surge stock screener | `/screens/volume-surge.html` | Total traded volume, baseline and end-of-day limitation. |
| 20-day breakout screener | `/screens/20-day-breakout.html` | Strict close-vs-prior-high comparison and volume confirmation. |
| Near 52-week high screener | `/screens/near-52-week-high.html` | Closing-price reference, distance formula and incomplete-year caveat. |
| Relative strength vs Nifty 50 | `/screens/relative-strength.html` | Percentage-point return difference, distinct from RSI. |
| Minervini trend template screener | `/screens/minervini-trend-template.html` | Exact adaptation and its composite-score substitution. |
| AlphaNova calculations | `/methodology.html` | Formulas, factor weights, missing-data behavior and timing. |
| AlphaNova pricing | `/pricing.html` | Current free access, five saved-screen limit and separate broker costs. |

**Observed competition:** the search for Nifty 500 delivery-volume screeners surfaced [Trendlyne’s delivery screen](https://trendlyne.com/fundamentals/stock-screener/71832/stocks-with-high-delivery-percentage/index/NIFTY500/nifty-500/), [Research 360’s volume/delivery screener](https://www.research360.in/screeners/volume-and-delivery-stock-screener), and [Moneycontrol’s delivery tables](https://www.moneycontrol.com/india/stockmarket/stock-deliverables/marketstatistics/indices/nifty-500-7.html). This establishes existing category coverage, not a stable rank order or evidence that AlphaNova can outrank them. AlphaNova’s proposed distinction is transparent calculation detail and direct access to reproducible presets.

**Template:** title `[condition] stock screener | AlphaNova`; unique description; direct definition; matching preset link; exact rules imported from the product; calculation explanation; illustrative worked example; interpretation checklist; specific limitations; one real question/answer; source links; related guides. Every published guide contains substantial editorial material beyond variable substitution.

**Data and maintenance:** `content/seo/screens.mjs` owns unique explanations; `src/screens.js` owns executable rules. `scripts/generate-seo.mjs` builds static pages, sitemap and text files during `npm run build`. Review guide prose and the fixed modification date when rules or methodology change. Dates must reflect reviewed content changes, not every build. The guides publish no current picks, fabricated market data or stale result counts.

**Expansion gate:** validate indexing and query impressions for this first cohort before adding pages. Next candidates are pullbacks, fresh golden crosses and low-volatility screens, but only with distinct examples and documented definitions. Company profiles require reliable dated data, adequate history, useful company-specific context and permitted source usage. Empty, duplicate or unmaintainable profiles should not be generated.

## AI search implementation and measurement

Added readable definitions, formulas, sources, current product/pricing facts and plain-text discovery links. `llms.txt` is an optional aid; no citation or ranking improvement is claimed. Google explicitly says there are no additional technical requirements or special AI files needed for its AI search features. [Google Search Central](https://developers.google.com/search/docs/appearance/ai-features)

Crawler roles matter: OpenAI’s **OAI-SearchBot** controls automatic search discovery; **GPTBot** is used for model training. They can be configured independently. **ChatGPT-User** is for user-triggered visits, not automatic search inclusion. The existing wildcard robots policy already allows the public documentation, so no training-policy change was necessary. [OpenAI crawler documentation](https://developers.openai.com/api/docs/bots)

Google Search AI features use Googlebot controls; Google-Extended is a separate control for some other Google uses. Do not claim that blocking a training crawler necessarily prevents search citation. [Google’s controls guidance](https://developers.google.com/search/docs/appearance/ai-features#control)

Record a baseline after deployment, then compare monthly. This is a recommended measurement plan, not an automation created by this task. Suggested prompts:

1. What is AlphaNova Terminal?
2. Is AlphaNova free?
3. Where does AlphaNova get its market data?
4. How does AlphaNova calculate delivery accumulation?
5. Nifty 500 stock screener with delivery analysis
6. NSE volume surge screener with explained rules
7. How do I screen for 20-day closing breakouts?
8. Relative strength versus Nifty 50 vs RSI
9. Why do 52-week highs differ between stock screeners?
10. Minervini trend template screener India

For each platform, run each prompt 3–5 times and record date, model/platform, locale, prompt, brand mention, citation URL, recommendation, competitors and sample count. Keep retrieved, cited, mentioned and recommended outcomes separate. None of these platform tests was performed here, so the current rates are **unknown**, not zero. Use Search Console for Google impressions/clicks and landing-page performance; its general Web reporting includes AI features rather than providing a separate cross-platform AI visibility report.
